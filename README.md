# AI 开工参谋

准备做一个项目，先选一套合适的 AI。

AI 开工参谋是一个面向项目启动阶段的模型与 Agent 选型 Skill。根据目标交付物、重要性、预算、隐私和现有工具，核验候选模型及价格，给出主力、备选、执行工具和首阶段验收建议。

## 它能帮你做什么

- **选模型**：从实际任务出发，比较具体型号、能力限制、使用渠道和适用条件。
- **查依据**：按任务需要打开官方资料，核对型号、提供状态和价格，保留来源及查询日期。
- **看费用**：区分 API、订阅和工具费用；需要估算总成本时，结合明确的用量或假设计算。
- **配工具**：说明“具体模型 → Agent 或接入渠道 → 首个建议交付物”，核验工具与模型的接入关系。
- **安排评审**：对重要项目，提供多个模型独立完整规划、互读全文交叉评审、依据证据汇总的安排与提示词。
- **交接执行**：给出备选切换条件、检查点、验收建议及待验证事项。

Skill 不内置一份永久有效的模型排行榜。型号、价格、可用状态等动态信息需要在实际使用时核验；联网不可用时，只提供选型框架和待核验项。

## 适合什么时候用

- 新项目启动前，不确定该用哪个模型和工具。
- 准备购买新套餐，想先比较现有订阅与新增支出。
- 已有候选模型，希望按项目条件核对优缺点和价格。
- 项目较重要，需要不同模型分别做规划并相互评审。

## 使用前提

使用能够加载 `SKILL.md` 及相对路径参考文件的 AI 助手。完整核验需要宿主提供联网搜索和网页读取能力；Skill 本身不提供模型额度、外部账号或多模型调用接口。

下载本仓库后，将完整目录保留为 `ai-kickoff-advisor`，按照所用平台的 Skill 安装方式加载。不要只复制 `SKILL.md`，它还会按需要读取 `references/selection-guide.md`。

如平台没有 Skill 加载入口，可以把完整目录作为可读材料交给助手，并明确要求先读取 `SKILL.md`、按其中的相对链接读取参考文件。实际支持范围取决于宿主平台。

## 直接这样开始

### 轻量项目

```text
用 AI 开工参谋帮我选型。
我准备做一个自己使用的小工具，重要性 2 分，预算有限，
尽量利用已有订阅。请推荐合适的模型和执行工具，
说明理由，以及第一步应该做出什么。
```

### 重要项目

```text
用 AI 开工参谋帮我选型。
我准备做内部知识库，主要处理中文制度和业务文档，
希望查询时能看到答案对应的原文。重要性 4 分，
资料不能离开公司指定环境，预算待定。
请比较合适的模型和工具，说明价格依据、部署条件、
待确认事项，以及第一阶段的验证方式。
```

### 已有候选

```text
用 AI 开工参谋比较我列出的候选模型。
请保留指定厂商和档位的全部比较位置，结合我的项目需求
推荐主力和备选，列出价格、限制、来源和查询日期。
没有证实的能力或价格，请明确说明。
```

## 重要性与工作深度

重要性由使用者按失败代价给出，范围为 1–5 分。

| 重要性 | 默认安排 |
| --- | --- |
| 1–2 分 | 快速筛选，核验最终推荐，给一个合适的型号及开工建议 |
| 3 分 | 给主力与备选，可选一次全文交叉评审 |
| 4–5 分 | 更深入地核验相关候选与部署条件，提供二至三个模型的协作规划和阶段验收建议 |

用户明确指定的比较范围、推荐数量和硬约束优先于默认安排。证据不足时会缩小结论，不为凑齐数量推荐无法证实的型号。

## 多模型协作怎么安排

1. 各模型在独立会话中读取同一份简报，分别提出完整规划。
2. 收齐后互读其他方案全文，指出遗漏、分歧和有依据的改进。
3. 依据证据、约束和验收标准汇总，保留待验证项。

多个模型赞同，不等于事实已被证实。实际调用与资料传输需要相应工具能力和授权；仅提供安排与提示词时，不会声称评审已经执行。

## 范围与限制

- 负责选型、工具选择、协作安排、验收建议和交接提示词。
- 不把项目背景或重要性评分当作开始实际研究、开发或对外操作的授权。
- 官方可用与用户账号可用分别判断；未确认的账户权限会保留条件。
- 未专项实测时，不声称某型号在该项目最准确。
- 隐私和部署要求属于硬约束，不为补齐候选而放宽。
- 实际行为与效果取决于执行模型、宿主工具、可访问资料和用户提供的信息。
